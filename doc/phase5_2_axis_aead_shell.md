# Phase 5.2 — AXI4-Stream AEAD shell

This phase adds `ascon_aead128_axis`, a high-throughput stream-facing shell around
the buffered AEAD core.

## Scope

Implemented:

- `rtl/axi/ascon_aead128_axis.v`
- `sim/tb/tb_ascon_aead128_axis.v`
- simulation targets for encrypt/decrypt and RPC 1/2/4/8
- synthesis target for the AXIS wrapper

Not implemented yet:

- AXI-Lite register file
- DMA engine
- memory master
- combined runtime encrypt/decrypt selection

## Interface

Job control is still direct signals:

```text
start_i/start_ready_o
key_i
nonce_i
ad_bytes_i
msg_bytes_i
tag_i
result_valid_o/result_ready_i/result_tag_o/result_auth_ok_o
```

Data movement uses AXI4-Stream:

```text
s_axis_ad_*      associated-data input
s_axis_data_*    plaintext/ciphertext input
m_axis_data_*    ciphertext/plaintext output
```

The `DECRYPT` parameter selects encryption or decryption at elaboration time.
This preserves the area discipline used throughout the project: synthesis only
instantiates the selected datapath.

## Byte order

AXIS byte order is normal stream order:

```text
tdata[7:0]       = byte 0
tdata[15:8]      = byte 1
...
tdata[127:120]   = byte 15
```

The wrapper uses the Phase 5.1 adapters to convert into the internal ASCON
block layout.

## `tlast`

Input `tlast` is accepted and forwarded through the ingress adapters, but the
current AEAD core is length-driven. The authoritative byte counts are
`ad_bytes_i` and `msg_bytes_i`.

Output `tlast` is generated by this wrapper from `msg_bytes_i`.
